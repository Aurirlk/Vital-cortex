## 工作流 A：设备数据面（MQTT + EMQX）

**A-1 依赖与迁移**
- `pom.xml` 加 `org.eclipse.paho.client.mqttv3`（与现有 okhttp/neo4j-driver 同风格的最小依赖；不引 Spring Integration）。
- 新迁移 `Data/02_迁移脚本/13_device_and_mcp.sql`（**必须**同步加进 `docker-compose.yml` db 挂载，命名 `18-migrate-13-device-mcp.sql`）：
  - `device`：id, user_id, device_sn UNIQUE, name, type(heart_rate/bp/scale/glucose/other), secret_hash CHAR(64)（SHA-256）, status, last_online_time, create_time/update_time
  - `device_data`：id, device_id, user_id, metric VARCHAR(50), value DECIMAL(10,2), unit VARCHAR(20), recorded_at, raw JSON, create_time；索引 (user_id,metric,recorded_at)、(device_id,recorded_at)
  - `mcp_token`：id, user_id, token_hash CHAR(64) UNIQUE, name, status, last_used_time, create_time（工作流 B 用，一起建）

**A-2 后端 ingestion**
- `core/iot/` 新包：`MqttConnectionManager`（Paho 封装：连接参数、自动重连、**broker 不可达时 fail-soft 降级**，照 Neo4j/Redis 懒连接模式保证 CI 裸机 `mvn verify` 仍绿）、`DeviceIngestionService`（订阅 `devices/{sn}/data`：校验 sn↔device 绑定与 secret → 写 `device_data` → **镜像写 `user_health`**（metric→`health_model_config` 解析 + ≥5 分钟节流，让现有 AI 工具/数据智能体/超标告警/报告零改动吃到设备数据）→ 复用 valueRange 阈值判定超标 → `UserNotifier.send(FOLLOWUP)` 触达 + WebSocket 实时推）。
- Mapper 三件套（MyBatis + XML，项目主流风格）：`DeviceMapper`、`DeviceDataMapper`（+ `mcp_token` 的 Mapper）。
- 设备 REST API `controller/DeviceController.java`（JWT 用户态）：列表/绑定（生成 sn+secret，secret 仅回显一次）/解绑/最新读数；EMQX 的 HTTP 认证回调放 `/crm/mqtt/auth`、`/crm/mqtt/acl`——**复用 `CrmApiKeyInterceptor` 的 fail-closed 保护**（它已罩 `/crm/**`），无需新拦截器。

**A-3 基础设施**
- `docker-compose.yml`：加 `emqx` 服务（1883/18083，HTTP 认证指向后端 `/crm/mqtt/auth`）；backend env 加 `MQTT_BROKER_URL`；**顺带补 backend healthcheck + `server.shutdown: graceful`（E5 收口）**；`.env.example` 补键并按既有分级注释风格标注（MQTT 缺省 fail-soft）。

**A-4 前端与演示物**
- 新页 `views/user/MyDevices.vue`（列表/绑定/解绑/最新读数/在线状态）；`router/index.js` `/user` children 加一条即可自动进菜单（`Main.vue:317` 注释确认无需改菜单组件）。
- `tools/device_simulator.py`：MQTT 模拟设备（可配 sn/interval/指标），**无硬件即可演示全链路**；`hardware/` 新目录：ESP32 + MAX30102 接线说明 + MQTT 发布示例 sketch（作品集叙事用）。

## 工作流 B：MCP Server（平台对外暴露健康事实）

- 依赖：官方 **MCP Java SDK**（`io.modelcontextprotocol.sdk:mcp`，实施时锁最新稳定版；用其 jakarta servlet SSE transport，**不引 Spring AI**——遵守 README「Spring AI 不进主线」约束；若 SDK 与 Boot 3.5 兼容不顺，备选手写 JSON-RPC/SSE 最小实现，约 300 行）。
- `core/mcp/server/`：`McpServerConfig` 注册 4 个工具，**全部桥接到现有 Tool 实例**（`ToolRegistry.get(name).execute(args)`，请求线程内先 `ToolContext.setPhoneAndUserId/setIdentity` 注入 PAT 解析出的身份——复用既有审计与越权语义，零逻辑复制）：
  - `get_latest_vitals`（最新读数，device_data+user_health 合并）
  - `get_vitals_trend`（近 N 天趋势，桥 `query_health_records`）
  - `get_health_records`（结构化记录，桥 `query_health_records`）
  - `list_devices`
- 认证：`/mcp/**` 用 PAT（`Authorization: Bearer mkp_...`）——`McpTokenInterceptor` 仿 `CrmApiKeyInterceptor`（`InterceptorConfig.java:74-76` 的注册样式）；发 token 的用户端接口挂 JWT，hash 存储、可吊销。
- 测试：4 个工具桥接单测（沿 `QueryHealthRecordsToolTest` 范本：mock mapper + ToolContext 身份 + 越权断言）、PAT 拦截器单测。
