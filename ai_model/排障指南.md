# Qwen2.5-7B 微调 - 问题与解决方案

## 问题清单

### 问题 1: PowerShell 编码损坏（最严重）

**现象**: 使用 PowerShell 的 `-replace` 操作符批量替换 Java 文件中的中文字符后，238 个文件的 UTF-8 编码被损坏，出现 `管理?`、`统计?` 等乱码。

**根因**: PowerShell 的字符串操作会破坏 UTF-8 多字节中文字符的编码。

**解决方案**:
```python
# 使用 Python 脚本处理中文内容
with open(filepath, 'r', encoding='utf-8') as f:
    content = f.read()
content = content.replace('旧中文', '新中文')
with open(filepath, 'w', encoding='utf-8') as f:
    f.write(content)
```

**教训**: PowerShell + 中文 = 灾难。始终使用 Python 处理中文内容。

### 问题 2: 数据集格式不符合 LLaMA-Factory

**现象**: 原始数据集将多轮对话硬编码在 instruction 字段中：
```json
{"instruction": "<user>: 问题 <bot>: 回答 <user>: 追问", "output": "回答"}
```

**影响**: 模型把 `<user>:` 等字符当成需要学习的文本，导致输出乱码。

**解决方案**: 使用正则解析并转换为标准 Alpaca 格式：
```python
import re

def parse_multi_turn(instruction_text):
    parts = re.split(r'(<user>:|<bot>:)', instruction_text)
    history = []
    current_instruction = None
    i = 0
    while i < len(parts):
        part = parts[i].strip()
        if part == '<user>:' and i + 1 < len(parts):
            user_msg = parts[i + 1].strip()
            if i + 2 < len(parts) and parts[i + 2].strip() == '<bot>:' and i + 3 < len(parts):
                bot_msg = parts[i + 3].strip()
                history.append([user_msg, bot_msg])
                i += 4
            else:
                current_instruction = user_msg
                i += 2
        else:
            i += 1
    return history, current_instruction
```

**正确格式**:
```json
{
  "instruction": "系统提示词",
  "input": "用户问题",
  "output": "模型回答",
  "history": [["历史问题", "历史回答"]]
}
```

### 问题 3: 系统提示词位置错误

**现象**: 把用户问题放在 instruction 字段，系统提示词放在 input 字段。

**影响**: 模型无法正确理解对话上下文。

**解决方案**: 按照教程要求：
- `instruction`: 系统提示词（角色定义）
- `input`: 用户问题
- `output`: 模型回答

```python
SYS_PROMPT = "# Role: 三甲医院资深全科医生\n## Profile: 拥有20年临床经验..."

record = {
    "instruction": SYS_PROMPT,
    "input": user_question,
    "output": answer,
    "history": []
}
```

### 问题 4: dataset_info.json 注册失败

**现象**: LLaMA-Factory 报错 `Undefined dataset huatuo_medical_small in dataset_info.json`

**根因**: 数据集注册文件没有正确复制到 LLaMA-Factory 的 data 目录。

**解决方案**:
```bash
# 1. 复制数据文件
cp /root/zhikangyun/dataset/*.json /root/LLaMA-Factory/data/

# 2. 注册数据集
cd /root/LLaMA-Factory/data
python -c "
import json
with open('dataset_info.json','r',encoding='utf-8') as f:
    di = json.load(f)
di['huatuo_medical'] = {
    'file_name':'train.json',
    'formatting':'alpaca',
    'columns':{'prompt':'instruction','query':'input','response':'output','history':'history'}
}
with open('dataset_info.json','w',encoding='utf-8') as f:
    json.dump(di, f, ensure_ascii=False, indent=2)
"
```

### 问题 6: PyTorch CUDA 版本不兼容

**现象**: 训练时显示 `device: cpu`，无法使用 GPU。

**根因**: 安装的 PyTorch 版本与服务器 CUDA 版本不匹配。

**解决方案**:
```bash
# 检查 CUDA 版本
nvidia-smi  # 查看 CUDA Version

# 安装对应版本
pip install torch --index-url https://download.pytorch.org/whl/cu128 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

from transformers import AutoModelForCausalLM, AutoTokenizer

### 问题 11: HuggingFace 无法访问

**现象**: `pip install transformers` 后运行报错 `HTTPSConnectionPool(host='huggingface.co', port=443): Failed to establish a new connection: [Errno 101] Network is unreachable`

**根因**: 部分云服务器无法直接访问 huggingface.co。

**解决方案**: 使用 ModelScope（魔搭社区）下载模型：
```bash
pip install modelscope -i https://pypi.tuna.tsinghua.edu.cn/simple
python -c "from modelscope import snapshot_download; snapshot_download('Qwen/Qwen2.5-7B-Instruct', cache_dir='/root/zhikangyun/model')"
```

### 问题 12: VLLM 启动报 CUDA Out of Memory

**现象**: VLLM 启动时报错 `torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 260.00 MiB. GPU 0 has a total capacity of 79.32 GiB of which 235.62 MiB is free. Process 955731 has 72.69 GiB memory in use.`

**根因**: 服务器与其他用户共享 GPU，另一用户的进程占用 72 GiB 显存，剩余空间不足以加载 7B 模型（需 ~14-16 GB）。

**解决方案**:
1. 协调其他用户释放 GPU 显存
2. 或等待其他用户训练完成后重试
3. 可使用 `nvidia-smi` 查看显存占用情况

---

### 问题 13: 服务器无法重启

**现象**: Ubuntu 22.04 最小化安装，缺少 `reboot`、`shutdown`、`systemctl` 等命令，无法通过 SSH 重启服务器。

**解决方案**: 需通过云平台网页控制台执行重启操作（华为云 → ECS → 停止/启动）。

---

### 问题 14: NVIDIA GPU Reset 不支持

**现象**: 执行 `nvidia-smi --gpu-reset -i 0` 返回 `The following GPUs could not be reset: GPU 00000000:8A:00.0: Not Supported`

**根因**: NVIDIA A800 不支持软件级别 GPU 重置。

**解决方案**: 只能通过重启服务器或协调其他用户释放显存。

---

### 问题 15: CUDA Context 泄漏

**现象**: `nvidia-smi` 显示显存占用 74 GiB，但进程列表为空，无法通过 `kill -9` 释放。

**根因**: 训练进程异常退出后，CUDA 驱动未正确释放显存，形成"僵尸"显存占用。

**解决方案**: 需重启服务器才能彻底释放 GPU 显存。

## 关键教训

1. **PowerShell 编码问题** - 最大的坑，导致 238 个文件损坏
2. **数据格式转换** - 必须严格按照 LLaMA-Factory 要求的格式
3. **环境一致性** - Python 版本、CUDA 版本必须匹配
4. **小规模验证** - 先跑小数据集确认流程，再全量训练
5. **系统提示词** - 使用项目真实的 prompt，提升模型专业度
6. **网络限制** - 国内服务器优先使用 ModelScope 下载模型
7. **GPU 共享** - 多用户共享 GPU 时需协调使用时间
8. **重启权限** - 云服务器需通过控制台重启，SSH 无法直接重启
9. **显存泄漏** - 训练进程异常退出可能导致显存无法释放
