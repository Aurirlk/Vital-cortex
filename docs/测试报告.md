| `ReadOnlyDataSourceConfigTest` | 🔴 三条反射断言锁死「只读数据源不能破坏应用启动」：配置类必须带 `@ConditionalOnProperty`（否则顶掉 Spring Boot 的 `DataSourceAutoConfiguration`，主数据源不创建 → `No qualifying bean of type DataSource` → **启动失败**）、`@Bean` 方法不得接收 `DataSource` 参数、注入侧必须 `@Autowired(required=false)`。**这类缺陷编译期与全部单测都发现不了，只有真启动才暴露** |
| `AuthContextConsistencyTest` | 三条防回归断言：① 全仓 Controller 不得用 `@RequestAttribute("userId")` 取身份（应统一用 `LocalThreadHolder`）② `JwtInterceptor` 与 `InterceptorConfig` 两处白名单必须一致 ③ **`/ai/config` URL 空间只允许 `AiConfigController` 一个类声明**（此前被 `AiController` 瓜分，管理员端点与普通用户端点混在一起） |
| `DataAgentPipelineTest`（本轮扩充） | **步骤 9 EXECUTE 与步骤 10 REPORT 此前零覆盖**（`dataSource` 恒 null → 必然 NPE）。现用 mock 数据源打通：EXECUTE 返回 rowCount/columns；REPORT 开启时生成、关闭时 `SKIPPED`；同步链路 `result.steps` 回填十步 |

> `SqlGuardTest` 曾真实暴露 3 个可绕过漏洞（注释内联、大小写混淆、空白截断），均已修复并回归通过。

### 写单测时踩到的两个坑（Mockito 相关，供参考）

1. **varargs 必须整体匹配**：`JdbcTemplate` 的 `queryForObject` / `queryForList` 都有
   `(String, Class, Object...)` 与 `(String, Object...)` 两个重载，裸 `any()` 会被误配到 `Class`
   形参，导致 stub 静默不命中、返回 `null`。正确写法：`any(Object[].class)`。
2. **注入字段要沿类链向上找**：目标若是子类（测试桩），`getClass().getDeclaredField()`
   找不到父类字段，会抛 `NoSuchFieldException`（`DataAgentPipeline` 里是同的，测试桩则是子类）。
