### 3.2 Bug 清单

| 编号 | 描述 | 严重程度 | 状态 |
|------|------|----------|------|
| BUG-001 | 无 | - | - |
| BUG-002 | `DepartmentMapper.xml` 里两处裸写 `<>` 不是合法 XML → MyBatis 解析失败 → **服务启动直接失败**；同时 `AppointmentMapper.xml` 四处列名写错（`u.user_phone` 应为 `u.phone`），干净部署下「我的预约」一律 `ERROR 1054`。**两者都不被任何既有测试覆盖**（无测试启动 Spring 容器） | 高（启动阻断 / 功能不可用） | 2026-10-10 已修复，并新增 `MapperXmlParseTest` 覆盖该类问题 |
| BUG-003 | AI 流式对话中用户中途离开页面（切标签页/刷新）时，SSE 回调异常一路冒到 `chatStream` 的 catch 直接 return → **整轮 AI 回复既不推送也不入库**，几十秒的深度思考结果永久丢失 | 高（数据丢失） | 2026-10-10 已修复（`StreamSink` 区分断开与真故障），回归见 `AiStreamSinkTest` |
| BUG-004 | 设置页「预约提醒/订单通知/AI 对话通知」等开关**无任何后端代码读取**，为纯装饰；`notification.title`/`link_url` 未搬运到出参，业务通知无标题且点不动 | 中（功能形同虚设） | 2026-10-10 已修复（`UserNotifier` + 9 个触发点），回归见 UT-005~UT-008 |

### 3.3 测试结论

单元测试（364 例，`mvn -o test`）全部通过。

> **本轮最重要的结论不是「都通过了」，而是「通过不代表能跑」**：
> BUG-002 在修复前，`mvn test` 是全绿的，但服务**根本启动不起来**。
> 原因是本项目没有 `@SpringBootTest`，容器与 Mapper XML 从未被真正加载。
> 现在这部分由 `MapperXmlParseTest` 静态兜底，但**仍然没有真正的集成测试** ——
> SQL 在 MySQL 上是否真能执行、服务能否真正 boot 起来，仍建议在部署环境做一次冒烟。
