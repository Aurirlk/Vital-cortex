## 一、平台定位

VitalCortex 是 AI-Native 的个人健康智能体平台：以「真实健康数据 + 受控 NL2SQL 数据智能体 + 多智能体对话编排 + 混合 RAG 知识库」为核心，覆盖**用户端健康自管理**、**医生端辅助**、**管理后台运营** 三条业务线。

- 后端：Spring Boot 3.5 / Servlet MVC / JDK 17
- 前端：Vue（热更新、免构建）
- AI：OpenAI 兼容协议（DeepSeek 云端 / 自部署 `HealthPulse-Qwen2.5-7B` vLLM），Provider 工厂 + 熔断器

## 四、数据智能体（受控 NL2SQL）— ✅ 开发完成

自然语言提问 → 真实 SQL → 真实数据 → 分析报告。整条链路是**十步流水线**，两步安全动作（词法守卫 + 租户重写）是**唯一出口**，命中风险模式一律 **fail-closed**。

![数据智能体流水线](docs/assets/02-data-agent-pipeline.png)

| 步骤 | 名称 | 职责 |
|---|---|---|
| 1 | 意图识别 | 判断闲聊还是数据分析请求 |
| 2 | 查询增强 | 结合上下文把问题改写为独立、可检索的规范查询 |
| 3 | 数据表召回 | 从全库召回与问题相关的候选表 |
| 4 | 表关系分析 | 分析候选表外键关系，为 JOIN/子查询提供依据 |
| 5 | SQL 生成 | 依据 schema 与表关系生成只读 SQL |
| 6 | 语义一致性校验 | 校验 SQL 是否真正回答了用户问题 |
| 7 | 安全守卫 | 词法校验：拒绝 DML/DDL/多语句/注释/系统库/黑名单表 |
| 8 | 租户隔离重写 | 删除模型写的租户谓词，无条件追加当前主体条件 |
| 9 | 执行查询 | 参数化执行，行数与时长为硬上限 |
| 10 | 生成报告 | 基于真实结果生成 Markdown 分析报告（可含 ECharts 图表） |

**三端入口**：`/user/data-agent`、`/doctor/data-agent`、`/data-agent/admin`
**实时性**：步骤事件经 SSE 实时推送到前端 `AgentWorkflow.vue`，全流程可见、可中断、可回看历史。
**运行时开关**：`DataAgentConfigHolder`（`system_config` 组 `data_agent`），管理员后台可改。

### 4.1 安全机制（双守卫，fail-closed）

| 守卫 | 类 | 职责 |
|---|---|---|
| 词法校验 | `MySqlAiSqlGuard` | 只读词法校验 + 关键词黑名单；子查询 / CTE / 隐式逗号连接 / 白名单外表一律拒绝 |
| 租户隔离重写 | `TenantSqlRewriter` | 逐表覆盖，无条件追加当前主体条件，杜绝越权读他人数据 |

> 安全唯一出口 `DataAgentPipeline.safeRewrite()`：初次生成与故障修复重试两条路径都过守卫。

## 五、AI 智能体架构（Multi-Agent + ReAct + 混合 RAG）

系统 AI 能力由三层构成：意图路由 → 工具增强推理 → 知识检索。

### 5.1 Multi-Agent 协调（AgentCoordinator）

`AgentCoordinator` 作为 Supervisor 中枢，基于**外部化意图词表**（`CrmConfig`）将问题路由到最合适的专科 Agent：

```
用户输入 → AgentCoordinator（意图识别）
   ├── 全科医生 Agent  → 症状分析 + 分诊建议
   ├── 营养师 Agent    → 饮食规划
   ├── 心理咨询师 Agent → 情绪疏导
   ├── 报告分析师 Agent → 体检报告解读
   ├── 健康助手 Agent   → 通用健康咨询
   └── 全能助手 (default) → 兜底
```

### 5.2 ReAct Agent（工具增强推理）

通过 **OpenAI function calling**（非正则解析）驱动 ReAct 循环，最多 5 轮自主决策，调用 6 个本地工具：

| 工具 | 数据来源 | 说明 |
|---|---|---|
| `search_drug` | `ai_data/drugs.json` | 药品搜索，返回名称/价格/厂商 |
| `get_health_data` | MySQL `user_health`（按指标字典白名单，LLM 不产 SQL） | 用户健康指标查询 |
| `search_knowledge` | 向量库 + MySQL | 知识库语义检索（混合） |
| `web_search` | 博查/Tavily/DuckDuckGo | 联网搜索最新信息 |
| `get_chat_history` | SQLite | 查询聊天历史 |
| `execute_sql` | SQLite（只读+租户隔离） | 只读 SQL 查询 |

> 每轮工具调用的**参数、结果、状态**随会话落库，支持审计回放。

### 5.3 混合 RAG 检索

文章发布时经 **ingestion 管线**（分块 `ChunkUtil` → 嵌入 `EmbeddingService` → 入库 `KnowledgeIngestionService`）自动灌入向量库；检索时**向量（余弦相似度）+ MySQL LIKE 双路召回，RRF 融合排序**，回答附引用溯源。

```
文章发布 → 分块 → 嵌入 → 向量库入库（ingestion 自动联动）
用户提问 → 向量召回 + MySQL LIKE 召回 → RRF 融合 Top-K → 注入 AI 上下文（带引用）→ 基于文章生成回答
RAGAS 评测（真实检索 + LLM 打分：精确度/忠实度/相关性）
```

> RAG 质量看板（`/admin/ragMonitor`）展示真实 RAGAS 指标，替代原先模拟数据。

### 5.4 LLM Provider 工厂与韧性

`LLMProviderFactory` 运行时切换厂商，自带轻量熔断器与 429/5xx 重试：

- `DeepSeekProvider` — 云端 DeepSeek
- `LocalVllmProvider` — 自部署微调模型 `HealthPulse-Qwen2.5-7B`（vLLM，OpenAI 兼容，默认 `:8000`）
- `CircuitBreaker` — 故障快速失败、半开探测恢复

### 5.5 多智能体编排框架（claude 增强新增）

| 模块 | 位置 | 说明 |
|---|---|---|
| 编排框架 | `core/agent/orchestrator/`、`core/agent/registry/`、`core/agent/run/` | 多智能体任务编排、定义注册、运行记录 |
| 受众上下文 | `core/agent/Audience.java` | 对话受众/身份透传 |
| 新工具 | `crm/agent/tool/CallAgentTool.java`、`SearchKbTool.java` | Agent 互调、知识库检索 |

## 九、安全加固要点

| 项 | 实现 |
|---|---|
| 密码存储 | BCrypt 加盐哈希 |
| 登录令牌 | JWT 密钥外部注入，启动强校验（空/弱密钥拒绝启动）；会话版本号（锁定/登出/改密即失效） |
| 机器接口 | `/crm/**` 由 `CrmApiKeyInterceptor` 做 API Key 认证，fail-closed |
| SQL 注入 | 双守卫：`SqlGuard` + 数据智能体侧 `MySqlAiSqlGuard`/`TenantSqlRewriter` 逐表重写，风险模式 fail-closed |
| 文件上传 | 登录态 + 扩展名白名单 + 魔数校验 + 随机文件名（不可枚举） |
| XSS | AI 输出统一经 DOMPurify 白名单净化（防存储型 XSS） |
| 数据出境 | 健康档案发送第三方 AI 前自动脱敏（剔除姓名/手机号等 PII） |
| LLM 稳定性 | Provider 工厂 + 熔断器 + Sentinel 限流（登录/AI/上传） |
| 成本可观测 | 每次调用 token 用量落库（`ai_usage` 表） |

> 合规提醒：平台涉及敏感个人信息，正式商用前建议完成等保三级测评与个人信息保护影响评估。
