## 2. AI 工具应用场景

### 2.1 数据库设计
**使用工具**: Claude + OpenCode

**应用场景**:
- 设计论坛模块表结构（post、post_reply、post_like 等 7 张表）
- 设计医生预约模块表结构（department、hospital_doctor、appointment 等 5 张表）
- 设计测验、商城、随访模块表结构（共 13 张表）
- 生成建表 SQL、索引设计、默认数据

**效果评价**:
AI 工具能够快速生成符合规范的数据库表结构，包括字段类型、约束、索引设计。生成的 SQL 语法正确，可直接执行。通过 AI 辅助，数据库设计时间从预估的 2 天缩短到 2 小时，效率提升约 8 倍。

### 2.2 后端 API 开发
**使用工具**: Claude + OpenCode

**应用场景**:
- 生成实体类（Entity）、Mapper 接口、Service 接口和实现、Controller
- 生成 MyBatis XML 映射文件
- 实现业务逻辑（预约挂号、自动评分、订单创建等）
- 处理并发安全（乐观锁、唯一约束）

**效果评价**:
AI 工具能够理解业务需求，生成符合项目规范的代码。生成的代码遵循 Spring Boot 最佳实践，包括分层架构、统一响应封装、AOP 鉴权等。通过 AI 辅助，后端开发时间从预估的 5 天缩短到 1 天，效率提升约 5 倍。

### 2.3 前端页面开发
**使用工具**: Claude + OpenCode

**应用场景**:
- 设计小红书风格 UI 设计系统（design-tokens.css）
- 生成 Vue 3 组件（登录页、预约页、测验页、商城页等）
- 实现响应式布局、动画效果

**效果评价**:
AI 工具能够生成美观、符合设计规范的前端页面。生成的代码结构清晰，样式统一，响应式适配良好。通过 AI 辅助，前端开发时间从预估的 7 天缩短到 2 天，效率提升约 3.5 倍。

### 2.4 文档编写

### 2.5 AI 智能体子系统开发（v5.1 新增）

**使用工具**: Claude / OpenCode（智能体编排、架构设计、代码生成、安全审查）

**应用场景**:
- **多角色 Agent 编排**：基于 6 类健康角色（通用/健康分析/用药/饮食/运动/心理），由 `AgentCoordinator` 按意图路由，意图词表外部化到配置，避免硬编码。
- **ReAct 推理引擎**：用 OpenAI function calling 实现「推理-行动」循环（`BaseReActAgent` / `ReActAgent`），工具调用轨迹落库，含循环检测与末轮总结。
- **混合 RAG 管线**：`KnowledgeIngestionService`（ChunkUtil 分块 → Embedding → 本地向量库）+ `HybridRetriever`（向量语义 + MySQL LIKE 关键词，RRF 融合）；评测接入真实 RAGAS 指标。
- **Provider 抽象 + 熔断**：`LLMProviderFactory` 支持 DeepSeek / 通义 / 本地 vLLM 热切换，`CircuitBreaker` 异常率熔断。
- **安全护栏**：`SqlGuard`（SQL 只读 + 租户隔离）、`CrmApiKeyInterceptor`（/crm/** fail-closed）、JWT 密钥外部化、PII 脱敏、前端 DOMPurify。

**效果评价**:
AI 工具在「多文件联动改造 + 安全加固」类复杂任务上表现突出——先生成审查手册（`../DELIVERY.md`）梳理 P0~P2 与架构级项，再逐项落地修复并补 25 个单元测试。其中 `SqlGuardTest` 真实暴露 3 个可绕过漏洞，经回归验证已闭环。

### 2.6 企业级安全代码审查（v5.1）

**使用工具**: AI 智能体 + 企业级代码审查工作流（对标 LangGraph / RAGAS / OWASP 方法论）

**应用场景**:
- 四路并行审查 Agent 系统 / 多模态 / 架构 / 对标项，汇总 57+ 项问题并分级（P0/P1/P2/架构级）。
- 聚焦 SQL 注入、IDOR 越权、密钥硬编码、SSE 资源泄漏、XSS 等医疗系统高危面。
- 修复后产出可交付的 `../DELIVERY.md` 用户手册。

**效果评价**:
AI 驱动的分级审查 + 自动补测试，使安全加固从「经验式排查」转为「清单式闭环」，显著降低遗留漏洞。

## 3. AI 工具使用技巧

### 3.1 提示词设计
**好的提示词示例**:
```
创建医生预约模块的后端代码，包括：
1. 实体类：Department、HospitalDoctor、DoctorSchedule、Appointment、VisitRecord
2. Mapper 接口和 XML
3. Service 接口和实现
4. Controller

要求：
- 遵循项目现有规范（@Mapper、@Service、@RestController）
- 使用 Lombok @Data 注解
- 使用 @Resource 注入
- 预约功能需要乐观锁保证并发安全
- 生成完整的 CRUD 接口
```

**效果**: 明确的需求描述能够帮助 AI 生成更符合预期的代码。

### 3.2 代码审查
**使用 AI 进行代码审查**:
- 检查代码规范（命名、注释、格式）
- 检查潜在 Bug（空指针、并发问题）
- 检查性能问题（N+1 查询、索引缺失）
- 检查安全问题（SQL 注入、XSS）

**效果**: AI 能够发现人工审查容易忽略的问题，提高代码质量。

### 3.3 调试辅助
**使用 AI 进行调试**:
- 分析错误日志，定位问题原因
- 提供修复建议和代码示例
- 解释复杂的技术概念

**效果**: AI 能够快速理解错误信息，提供有效的解决方案，缩短调试时间。

## 5. 注意事项

### 5.1 AI 工具的局限性
- 生成的代码需要人工审查和测试
- 复杂业务逻辑可能需要多次迭代
- 无法完全替代人工思考和决策

### 5.2 最佳实践
- 明确需求描述，提供足够上下文
- 分步骤生成代码，逐步验证
- 保持批判性思维，不盲目信任 AI 输出
- 结合人工审查，确保代码质量

### 5.3 伦理考量
- 遵守学术诚信，明确标注 AI 辅助
- 保护数据隐私，不上传敏感信息
- 尊重知识产权，遵守开源协议
